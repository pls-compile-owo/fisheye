# 字幕链路设计（定稿）

> 记录时间：2026-11-18
> 状态：**设计定稿，未实现**。基线 1.0.29。
> 上游讨论：`docs/fisheye-2.0-方案.md`（定位与双轨）、`docs/广告识别复盘.md`（广告线）。
> 本文只讲「字幕」这一步：取什么 → 怎么压 → 给谁、给多少。

---

## 一、目标

一条 40 分钟视频的官方字幕是 **49,757 token**（实测，英文 AI 字幕）——占整条链路成本的 93%。

字幕链路的目标只有一个：**让 agent 用几百 token 判断「哪段值得读」，按需再取全文。**

三个不变量：
1. 摘要只给**决策依据**，不给结论
2. 全文永远保留**原文**（供引用），不翻译、不改写
3. 翻译**不进 fisheye**（下游化：B站 翻译轨有就用，没有就 agent 自己读）

---

## 二、现状（1.0.29）

| 环节 | 现在怎么做 |
|---|---|
| 取字幕 | `source.subtitles()`：官方字幕（原文轨）+ `translated`（B站 翻译轨） |
| 质量判定 | `assessSubtitleQuality`（bili.mjs），产出 quality 标记 |
| 落盘 | `-official-subs.txt` / `-plain.txt` / `-translated.txt` 三份全文 |
| 转写兜底 | whisper（`--audio` 或 `FISHEYE_AUTO_AUDIO`） |
| 字幕带 | `lib/band.mjs`（纯 JS，第三级兜底） |
| 下游使用 | 语义切分、广告 sub-keywords、精读建议 |

痛点：**全文直接给 agent**（49,757 token），没有分层。

---

## 三、链路设计

```
① 取字幕（原文轨 + 翻译轨）
   ↓ 选语言：有翻译轨 → 中文；否则原文
② 句子合并（相邻短句 → 20~40 字）
   ↓
③ 结构抽取（结论句 / 转折句 / 数字与专名 / 术语）
   ↓
④ 摘要生成（每段：head + keywords + info + claims + numbers）
   ↓
⑤ 全文按段落盘（seg-NN-subs.txt）
   ↓
⑥ 质量门控（score + warnings）
```

### 3.1 取字幕与语言选择

| 情况 | 用什么 | 理由 |
|---|---|---|
| 有翻译轨 | 翻译轨（中文） | 零成本、省 3.5 倍（49,757 → 11,615） |
| 无翻译轨 | 原文 | 不机翻（翻译下游化） |
| 无官方字幕 | 转写 → 字幕带 | 沿用现有三级降级 |

> 默认行为变化：**有翻译轨时默认用翻译轨**（现在默认给原文，翻译轨只落盘）。这是全链路最便宜的 3.5 倍。

### 3.1.1 实测：转写「成功」会遮挡烧录字幕带（待修，1.0.29 已确认）

**案例**：BV1FVWU6wEnp（15s 萌宠，字幕烧录在画面里）。

| 路径 | 实测结果 |
|---|---|
| `subs` 命令（独立跑） | ✅ 字幕带检测到 79%~85%（677-733/862），confidence=1，生成 12 行字幕带图 |
| `auto`（完整流程） | ❌ 转写"成功"12 字（内容 `字幕:J Chong`，BGM 误转）→ **直接跳过字幕带检测** → 真正的字幕完全没读 |

**根因**：`auto` 的降级链是「转写成功 → 跳过字幕带」，但**"转写成功" ≠ "转写有内容"**。

**修复方向**（尚未实现）：降级链改为「转写成功 **且质量 OK** → 跳过字幕带；否则继续跑字幕带」。

**字幕带来源的 subs 形态**（与文本字幕不同）：

```js
subs: { source: 'band', image: 'out/<id>-subs_12行.jpg', rows: 12, confidence: 'ok' }
// 不是文本，是图 + 行时间戳：agent 读图（~1000 token）或 OCR
```

### 3.2 句子合并

官方字幕常是碎片句（每句 5~10 字）。合并规则：

- 中文：相邻两句总长 ≤ 40 字，且前句不以句号/问号/感叹号结尾 → 合并
- 英文：相邻两句总长 ≤ 30 词，且前句不以 `.?!` 结尾 → 合并
- 时间戳取前句起点（合并句的「开始时间」）

收益：段落数 −20~30%，摘要不会抽到半句话。

### 3.3 摘要算法（实测校准，2026-11-18）

在可汗视频（2255s，英文 AI 字幕 1026 行 + 中文翻译轨 1088 行）上跑了 4 版 demo（`tools/subs-digest-demo*.mjs`），规律如下：

**四条必须遵守的规则**

| 规则 | 不遵守的后果（实测） |
|---|---|
| 关键词用 **TF-IDF**，不用词频 | 词频法每段都抽出 `grain, were, had, after`——全片高频词淹没段内特有词 |
| 停用词表要完整（英文 200+，中文 200+） | `were / had / after / even / 得到 / 苏联的` 全漏进关键词 |
| **广告句必须踢出摘要** | v2 段 2 的 info 抽成了 "Oil Control 洁面产品" 的广告口播 |
| head/info **截断到 60 字（中）/ 110 字符（英）** | 不截断时每段 170~200 token，截断后 90~140 |

**中文关键词的已知缺陷**：没有分词器时用 3~4 字窗口 + 去重叠，仍会把「迪亚科夫」拆成「迪亚科 / 亚科夫」、「布加耶夫」拆成「布加耶 / 加耶夫」。**可接受**——索引只用于"要不要读这段"的决策，片段不影响判断；要可读性就得引入分词（破零依赖）。

**一句话总结**：摘要怎么写 = TF-IDF 选词 + 完整停用词 + 广告句过滤 + 长度截断，四条缺一不可。

### 3.4 结构抽取

四条规则，中英各一套（硬编码，零依赖）：

| 类型 | 中文触发 | 英文触发 |
|---|---|---|
| 结论句 | 所以/因此/总之/这就是/由此可见 | so/therefore/thus/in short/that's why |
| 转折句 | 但是/然而/不过/其实 | but/however/actually |
| 数字与专名 | `\d+[年月日万亿%元]`、引号内内容、大写缩写 | numbers、quoted terms、ALLCAPS |
| 术语 | 反复出现的 2~4 字词（char-bigram 词频） | repeated noun phrases（词频） |

输出每段的：
- `claims`：结论句（最多 2 条）
- `turns`：转折句（最多 2 条）
- `numbers`：数字/专名（去重，最多 8 个）
- `keywords`：术语（最多 6 个，停用词过滤后按词频）

### 3.5 摘要生成（每段 ~45~140 token）

```js
{
  head: "信息量最高的那一句",       // 评分：关键词密度 + 数字数 + 是否结论句
  keywords: ["苏联", "间谍", "叛逃"],
  info: "关键词密度最高的一句",
  claims: ["所以最后他选择了叛逃"],   // 可空
  numbers: ["1985", "克格勃"],        // 可空
  lang: "en" | "zh",
  chars: 4200
}
```

**「首句」的定义**：不是字面第一句（B站 视频开头常是"大家好我是XX"），而是**评分最高的句子**——评分 = 关键词密度 × 2 + 数字数 × 1 + 是否结论句 × 2。

### 3.6 全文落盘（按段切片）

```
out/<id>/
  seg-01-subs.txt     ← 第 1 段全文（agent 按需 read）
  seg-02-subs.txt
  ...
  -official-subs.txt  ← 全片原文（保留，兼容旧行为）
```

agent 的判断：摘要不够 → `read seg-03-subs.txt`。

### 3.8 可压缩性判定（质量 ≠ 可压缩）

**质量**判的是"字对不对"；**可压缩性**判的是"有没有可抽的信息"。两者独立——字幕可以字全对、却完全没有可压缩内容。

**极限样本**：BV1FVWU6wEnp（15s，AI 生成萌宠鬼畜梗视频，7.4 万播放，标注"含 AI 生成内容"）。烧录字幕全文：

> 你喵难道没有教你 / 不要随便对人哈气 / 你这个坏坏哈基 / 左边一个公公 / 右边一个鸡基 / 给我乖乖站好 / 叮咚 叮叮咚 / 大狗大狗叫

字全对、无乱码、无 ♪ 噪声（质量合格），但**全是梗/拟声/押韵，没有事实、没有数字、没有逻辑承接**。摘要抽任何一句都没有信息量。

**判据（命中 ≥3 条 → `compressible: false`）**

| 判据 | 阈值 | 该样本 |
|---|---|---|
| 平均句长过短 | < 10 字 | ✅「左边一个公公」6 字 |
| 实词比过低 | < 40% | ✅ 大量拟声/语气（叮咚、坏坏、哈基） |
| 无数字 / 无专名 | 全片 0 个 | ✅ 一个都没有 |
| 句间语义连贯性低 | char-bigram 相似度中位数 < 0.1 | ✅ 一句一梗，无承接 |

**处置**

```js
subs: { source: 'band', compressible: false, confidence: 'none' }
// 语义：字幕这个证据源无效
// 不等于：这段内容无价值
```

`compressible: false` 说的是**字幕无法压缩**，不是**视频没价值**。本样本的价值恰恰在画面——"猫在跳舞"是可读的，只是它不在字幕里。

所以正确链路是：

```
字幕不可压缩 → 字幕证据作废（不产摘要）
     ↓
视频有没有价值？→ 看画面（必须读图才知道）
     ↓
画面可读（本例：猫跳舞）→ 有价值，读图
画面也不可读（纯黑屏 + 抽象字幕）→ 真·无价值，跳过
```

**这就是 `visualRequest` 的存在理由**：不是因为"没信息所以随便看看"，而是因为"字幕作废了，价值可能在画面，必须读图确认"。

**为什么要单独判**：只判质量时，这类视频的字幕会被当成有效证据，摘要抽出来是"梗句拼盘"，agent 读了反而被误导。`compressible: false` 让它诚实地说"这个证据源没信息"，而不是假装总结了内容。

### 3.9 质量门控

**字幕质量判定必须覆盖所有来源，不只是官方字幕。**

实测案例（15s 萌宠视频，无官方字幕）：whisper 转写"成功"，输出 12 字——内容是 `字幕:J Chong`（BGM/音效被误转），完全无信息。如果只按"转写成功"标记，这段字幕会被当成有效证据。

判据（三条任一命中 → `quality: 'noisy'`）：

| 判据 | 阈值 | 说明 |
|---|---|---|
| 字数过少 | < 10 字/分钟 | 15s 视频 12 字 = 48 字/分（不触发），但 5s 视频 2 字会触发 |
| **实词比过低** | 实词 < 30% | `字幕:J Chong` → 实词 0 → 命中 |
| 重复率过高 | 唯一行 < 40% | 已有 `uniqueRatio` 判据 |

转写来源额外加 `source: 'transcript'` 标记——agent 知道"这是听写的，人名可能错"。


`subsQuality: { score: 0~1, warnings: ["ai-generated", "low-confidence"] }`

- AI 字幕 → 标 `ai-generated`（可能有错字，agent 知道就行）
- 翻译轨 vs 原文 → 标 `translated`（术语可能不准）
- 不阻断、不降级，只标注

## 五、成本模型

| 形态 | 40 分钟视频 | 说明 |
|---|---|---|
| 全文（现状） | 49,757 | 直接给 agent |
| 摘要（每段） | **~90~140 token（实测）** | head + keywords + info + claims + numbers（中英都测过） |
| 9 段摘要合计 | **~1.1k token（实测）** | 决策成本（可汗 2255s） |
| agent 读 2 段全文 | +8k~12k | 按需 |
| **合计（典型）** | **~8k~12k** | 省 **76~84%** |

模型常数（沿用 `lib/budget.mjs`）：摘要按字算，1 字 ≈ 1 token。

## 六、边界与降级

| 情况 | 行为 |
|---|---|
| 无官方字幕、无转写 | 摘要为空，`coverage.subs = none`，agent 走画面 |
| 字幕质量差（`score < 0.5`） | 摘要照给 + warnings 标注，agent 自行决定信任度 |
| 语速极慢（chars/sec < 1） | 摘要里加 `sparse: true`（这段信息密度低）——可选 |
| 单段字幕为空（纯画面段） | `subs: null`，agent 只看画面 |

**不做**：
- 不机翻（翻译下游化）
- 不做 LLM 摘要（那是判断）
- 不保证摘要覆盖全文（抽取式必然遗漏——所以全文必须落盘）

## 八、验收标准

| 项 | 标准 |
|---|---|
| 摘要成本 | 40 分钟视频 ≤ 400 token（8 段） |
| 摘要可读性 | 每段 head 能独立说明「这段讲什么」（人工抽检 5 条） |
| 句子合并 | 碎片句比例下降 ≥20% |
| 语言选择 | 有翻译轨时默认中文（用可汗视频验证：49757 → 11615 → 摘要 ~360） |
| 全文可读 | `seg-NN-subs.txt` 可被 read 正常读取，时间戳保留 |
| 测试 | 新增 ≥8 用例，全量 242 → 250 |
| 性能 | 字幕处理耗时 <0.5s（40 分钟，纯 JS） |

## 九、不做的事

| 不做 | 理由 |
|---|---|
| 外部翻译接口 | 收益几十 token，维护成本是永久的；用「输出 JSON 可 pipe」代替 |
| LLM 摘要 | 判断层，归 agent |
| 全文翻译 | 错误做法：先翻全文（11,615）再摘要，比先摘要再翻贵 30 倍 |
| 摘要覆盖全文的保证 | 抽取式必有遗漏，所以全文落盘兜底 |
| 关键词保证可读（引入分词） | 索引只用于决策，char-bigram 片段可接受；要可读性就得破零依赖 |
