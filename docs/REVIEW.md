# 验证与评审流程

> 这份文档定义「怎么确认 fisheye 没坏」和「怎么让一个独立视角挑毛病」。
> 每次改完代码，按这里跑一遍。

---

## 一、快速验证（改完代码必做，约 10 秒）

```bash
cd fisheye

# 1. 语法
node --check fisheye.mjs
python -c "import ast; ast.parse(open('analyze_subs.py', encoding='utf-8').read())"

# 2. 单元测试（node test-danmaku-filter.js，51 断言）
node test-danmaku-filter.js

# 3. 自检（依赖/凭证/API/缓存/磁盘）
node fisheye.mjs selftest

# 4. 深度自检（+ 实测抽帧、字幕带定位）
node fisheye.mjs selftest --deep
```

**期望**：全部通过，`selftest` 无 `[!!]`。

> 注意：`[--]` 是「跳过」不是失败（例如视频无字幕轨、缓存为空），属正常。

## 二、功能回归（改了取帧/字幕/弹幕逻辑时）

用固定的几条测试视频，对比改动前后输出：

| 用途 | BV | 特征 | 关注点 |
|---|---|---|---|
| 短视频 + 无字幕 | `BV12F411E7Zi` | 109s，竖屏 1080×1920，动态字幕 | 竖屏 token 修正、字幕带置信度拒绝 |
| 短视频 + 官方字幕 | `BV1ziWP6qENy` | 114s，方屏，有 CC 字幕 | 官方字幕优先、弹幕热区 |
| 中视频 + 固定字幕 | `BV1h3W76wE6A` | 82s，横屏，底部烧录字幕 | 字幕带定位、变化率密度 |
| 长视频 + 广告段 | `BV1i4W86zEUS` | 2385s，40 分钟，4:35-6:49 是鱼油广告 | 12 张上限降级、广告段检测、不占帧 |

```bash
node fisheye.mjs auto BV1i4W86zEUS --budget 30000   # 长视频全流程
```

**关注这些输出**：

- `[比例]` 单张 token 估算是否随分辨率变化
- `[密度]` 目标帧间隔是否随变化率变化
- `[张数]` 是否触发「预算只够 N 张」降级
- `[字幕]` 官方字幕 / 烧录字幕带 / 无，三条路是否走对
- `[广告段]` 40 分钟视频是否检测到 04:40-06:40
- `[取帧]` 跳过广告的段，`内容实际` 范围是否合理

## 三、评审清单（六个维度）

改完重要逻辑后，按这份清单自查：

### 1. 正确性
- [ ] 边界条件：`--from` 大于 `--to`？`--budget 0`？视频 0 秒？
- [ ] 空数据：无弹幕 / 无字幕 / 无场景变化点时是否还能走通
- [ ] NaN / Infinity 是否可能进入计算（参数校验、除法）
- [ ] 时间戳精度：manifest 存 2 位小数（1 位会跨镜头）

### 2. 可移植性
- [ ] 没有硬编码的绝对路径
- [ ] 平台假设：路径分隔符（`path.join`）、命令行（`where`/`which`）、编码
- [ ] 外部依赖解析失败时有清晰报错

### 3. 资源管理
- [ ] 临时文件是否在所有路径（包括异常）都清理
- [ ] 子进程是否有超时
- [ ] 大文件（234MB mp4）是否流式处理而非全读内存
- [ ] `cache/` 是否有清理机制

### 4. 错误处理
- [ ] 失败时给的是「可操作的提示」还是「堆栈」
- [ ] 有没有 `catch {}` 静默吞掉关键错误
- [ ] 降级路径是否显式告知用户（而不是静默变差）

### 5. 一致性
- [ ] README 承诺的功能代码里都有
- [ ] README 的参数名和 CLI 实际解析一致
- [ ] 输出示例和实际输出格式一致
- [ ] `docs/` 里的描述和代码同步（改了代码要改文档）

### 6. 安全
- [ ] 外部输入（BV 号、时间参数）不能拼进命令行（只用 `execFile` 数组）
- [ ] 文件路径不能由外部输入直接构成（路径遍历）
- [ ] 凭证（SESSDATA）不会出现在日志、错误信息、out/ 产物里

## 四、让独立视角评审（subagent）

自己写完自己审容易有盲区。把这段发给一个**独立上下文**的 agent：

```
你是一个独立的代码评审员。评审项目：<项目路径>

第一步（必须实际执行）：
  node fisheye.mjs selftest
  node test-danmaku-filter.js
  node --check fisheye.mjs

第二步：按六个维度评审
  1. 正确性（边界、空数据、NaN）
  2. 可移植性（硬编码路径、平台假设）
  3. 资源管理（临时文件、子进程、大文件）
  4. 错误处理（失败提示、静默吞错、降级告知）
  5. 一致性（README 承诺 vs 代码实际）
  6. 安全（命令注入、路径遍历、凭证泄漏）

输出：按 🔴严重 / 🟠中等 / 🟡轻微 分组，每条给 `文件:行号` + 问题 + 复现 + 建议。
最后给 X/10 评级。

硬性要求：
- 只报能用代码证据支撑的问题（给行号）
- 不提泛泛的「建议加测试」，除非能指出具体哪个函数没测、有什么风险
- 已在 README「已知限制」声明的，标注「（已声明）」
- 没验证过的结论明确说「未验证」
- 不修改文件
```

**为什么要独立评审**：这个项目之前的评审发现过「零单元测试」「硬编码路径」「并发清理误删」三个真问题——都是写作者自己的盲区。
