## 一、第一性原理：fisheye 的本质

fisheye 是「agent 上游筛选视频内容的工具」。Agent 不缺判断力（它有 LLM），缺的是**把视频这个「海量、非结构化、token 巨贵」的原始物，压成「少量、结构化、token 便宜」的摘要**。

所以尺子一句话：**fisheye = 压缩，不是判断。**

- **压缩（该做）**：原始信息 → 结构化摘要（字幕/关键帧/弹幕高光）
- **判断（越界）**：替 Agent 决定「哪段是广告 / 哪段重要 / 话题边界在哪」
- **过度优化（该简化）**：为模糊收益养大坨复杂度（场景吸附三层）

## 二、定稿结论（四块分类）

### A. 核心压缩 —— 留，值得继续打磨

| 模块 | 压缩什么 |
|---|---|
| 官方字幕（getOfficialSubs） | 语音 → 文本 |
| 转写（whisper） | 音频 → 文本（无字幕兜底） |
| 关键帧网格（等间隔） | 画面 → n 帧 |
| 弹幕高光（summarizeDanmaku） | 几千弹幕 → 几个高光段 |

### B. 越界判断 —— 砍 / 降级

| 模块 | 判断什么 | 处置 |
|---|---|---|
| 广告检测七路（signals/） | 「哪段是广告」 | 🔪 砍六路，密度低谷降级「低互动段」+「广告词高光」（见广告识别复盘.md） |
| 精读建议打分排序（executor.mjs） | 「哪段重要、先看哪个」 | 🔪 降级为「信号强的片段列表」，不给排序/排除 |
| 语义切分 embedding（semantic.mjs fastembed+ruptures） | 「话题边界在哪」 | ✂️ 砍 embedding，留纯 JS 粗切（semantic-core.mjs） |

### C. 过度优化 —— 简化

| 模块 | 优化什么 | 处置 |
|---|---|---|
| 场景吸附 + 阈值阶梯 [0.3,0.15,0.08] + 去重（frame.mjs pickTimes） | 让帧「更好看」 | 🔪 砍三层，pickTimes 退回「等间隔 + 低互动段降权」 |
| 低互动段降权（w=0.3 可配置） | 省取帧 token | ✅ 保留（唯一量化的省 token 点） |

### D. 待定 —— 已逐一定案

| 模块 | 结论 |
|---|---|
| 字幕带检测（band.mjs） | ✅ **留**。定位「可选低频兜底」（第三级，转写失败才触发；纯 JS 检测 + tesseract OCR 惰性成本）。不动、不再投入。 |
| 产物完整性摘要（coverage） | ✅ **留，但简化呈现**。从「6 字段对象」退成「缺了哪几个」一行提示。价值是「压缩的诚实前提」——上游不能悄悄漏信息。 |
| 多平台适配器框架（platforms/） | ✅ **留**。最初的「解耦 B站」目标，是正确的架构预留。 |

## 三、瘦身后的 fisheye 长什么样

**核心四件套（全是压缩）：**

```
字幕/转写 → 等间隔关键帧 → 弹幕高光 → 低互动段（降权取帧）
```

**砍掉的是：** 广告精确分类、精读排序打分、话题精确分析、场景吸附三层。

**轻量保留：** 广告词高光（纯线索）、字幕带（低频兜底）、coverage（一行诚实声明）、多平台框架（架构预留）。
