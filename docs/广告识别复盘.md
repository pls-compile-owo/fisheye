## 一、这条线怎么走到这里的

广告识别从「调参」开始，最后演变成「反思它是否该存在」。完整历程：

1. **A 收紧边界**：去「同款」、buy 回溯 120→60s、密度合并 20→10s。高置信段精确率 16%→60%。
2. **C 分区词库**：按 B站 `tid_v2` 降级科技区「商单/赞助/下单」、汽车区「赞助」。消除 3 段明确误报。
3. **A 语义仲裁插槽**：`arbitrateAdSegments` 定义 judge 接口，但 judge 无实现（运行时零开销）。
4. **真值固化**：21 条人工标注（12 真广告 + 9 无广告）写入 `test/golden/ad-truth/`。
5. **乱码清理**：旧 8 条 golden 清空乱码文本（留密度信号），删 2 条靠乱码巧合假通过的。

调参过程中，用户提出「是不是花了太多精力在广告识别上」——由此转入复盘。

## 二、核心反思：七路广告检测是过度工程

七路信号 = 密度低谷 / 关键词 / 打点 / 片头 / 消费回溯 / 字幕关键词 / 字幕句式。

**三个理由：**

1. **省 token 量级很小，配不上七路复杂度。** 广告段在取帧计划里是「压缩/避开」，省的是「广告段取帧数 × 压缩系数」的量级。为这点收益投入七路 + 分区词库 + 语义插槽 + 21 真值，投入产出倒挂。

2. **判断广告本质是下游 Agent 的活，不是 fisheye 的。** fisheye 的职责是「在 token 预算内压缩、提取视频信息」（字幕/弹幕高光/关键帧/精读）。Agent 拿到信息后自己看画面就能判断广告，且比弹幕间接信号准得多。七路信号是「替 Agent 做它本就能做、且做得更好的判断」——越界。

3. **七路里真正干活的就两路，另五路是边角料。** mark/head/buy 覆盖面极窄（特定 UP 主定制），sub-keywords/sub-patterns 依赖字幕。真正有价值的是 density（低互动）+ keywords（广告词）。

---

## 三、关键洞察（思维链里的想法，避免以后重复推导）

- **「省 token」要避开的其实是「低价值段」，而密度低谷（低互动）本身就是这个代理**——不需要「是不是广告」的精确分类。这是整个重构的支点。
- **judge 是仲裁器，帮不了「检测 0 段」的 hardCase。** 虎门抽烟/F1 检测 0 段（无候选段），judge 无从仲裁；破产大王已 multi-hit（judge 不调用且缺的是边界不是判定）。所以语义仲裁对 3 条 hardCase 零帮助。
- **char-bigram 和 fastembed 都是「相似度」，不是「分类」。** 相似度对「同一词不同语境」（「我赞助了5台PS2」调侃 vs「本期由XX赞助」真广告）分辨力天生有限。质变需要 NLI/LLM 分类。fastembed 相似度是「花 python+100MB 买鸡肋」。
- **折中方案（降权）是「避开」和「照常」的统一。** 低互动段时长乘权重 w（0<w<1）：w=0 退化成完全避开，w=1 退化成照常。这不是新增特例，而是更通用的模型。

---

## 四、最终确定的方案（三点决策）

1. **折中取帧**：低互动段降权 w=0.3（可配置 `FISHEYE_LOW_ENG_WEIGHT`），既不完全避开（防误判低互动=低价值）也不照常（省 token）。
2. **广告词高光**：独立列表 `adKeywordHits`（[{t,text}]），纯线索、不参与任何决策。定位：「低互动段负责决策（取帧/精读降权），广告词高光负责解释（告诉 Agent 这段低互动可能因为啥）」。
3. **版本 1.0.30**（breaking change 但属内部字段，不升 2.0）。

// 低互动段（替代「广告段」）

  → [{ from, to, dur, ts, lowDensity }]   // 不再有 confidence / keywords

adKeywordHits = danmaku.filter(d => AD_KEYWORD.test(d.text))  // 去重 + 限量

// 取帧降权
