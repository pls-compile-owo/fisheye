# fisheye 2.0 总纲

> 完整设计（原 17 章）拆成 11 个模块文档。本文是总纲：定位、链路总览、不做的事、执行计划、验收。
> 模块索引见文末；原始整篇见 [fisheye-2.0-方案.md](../fisheye-2.0-方案.md)。

## 一、定位

**fisheye = 把视频压成「证据 + 成本」，不替 agent 判断。**

三条推论：

1. **用户是 agent，不是人。** 人类看图像便宜、读文字贵；AI 读文字便宜、看图像贵。fisheye 把 AI 的成本结构变成工程决策。
2. **判断权归 agent。** 判断「哪段是广告 / 哪段重要 / 话题边界在哪」是 agent 的活，它比规则准，而且它本来就要读。
3. **感知层保持机械。** 抽帧、拼图、字幕切片没有判断空间，不需要 agent 介入。

## 二、核心：成本优先链路（本次最大的改动）

### 2.1 旧链路的问题

按"信息完整性"排：字幕全文 → 弹幕 → 画面 → 精读。结果是**每样都读**：

| 40 分钟视频 | 旧链路 |
|---|---|
| 字幕全文 | 49,757 token |
| 拼图 38 张 | 45,600 token |
| **合计** | **~95,000 token** |

> **口径注（给未来的自己）**：38 张是 `grid` 命令的行为（1 分钟/张），**不是 `auto` 的默认**——auto 硬上限 12 张，按密度决策 40 分钟视频通常 2~4 张，预算封顶时只有 1 张（可汗实测：49,757 + 1,200 ≈ 51,000）。
> 所以诚实的对比区间是 **25~32 倍**（51k~64k → 2k），不是 47 倍。47 倍是"最贵对照"，保留在此仅作上限参考。

### 2.2 新链路：按成本排，读帧最后

```
① 段卡片（~80 token/段）       ← 先读：每段有什么证据、成本多少
② 字幕骨架（~45~140/段）       ← 不够再读
③ 弹幕高光 + 情绪分（~0）       ← 还不够再读
④ 画面 coarse（~1024/张）       ← 还不够再读
⑤ 画面 fine（~1024/段，5x5 也是一张图） ← 最后手段（agent 点名）
```

| 同一条 40 分钟视频 | 成本优先 |
|---|---|
| 段卡片 ×10 | ~800 |
| 字幕骨架 ×10 | ~1,200 |
| 弹幕高光 ×10 | ~0 |
| 帧 | **0（没读）** |
| **合计** | **~2,000 token**（对比 auto 默认 51k：**省 ~25 倍**；对比上限 95k：省 47 倍） |

### 2.3 纯文本链路两档

不跑全片场景检测（72s）：

| 档 | 含什么 | changeRate | 耗时 |
|---|---|---|---|
| `fast`（默认） | 字幕 + 弹幕 + 摘要 + 切段 | **null**（类型判定/低置信帧不可用） | **<5s** |
| `standard` | fast + 粗采样 changeRate（每 30 秒一帧，约 80 帧） | `estimated: true`（能支撑极端值判定） | **~15s** |

- 粗采样对 3.5 的极端判据够用（>1.2/秒 或 <0.05/秒 都是极端值，30 秒粒度可区分）
- 3.7 低置信帧定义中的"低变化率段"在 fast 档退化为**只用弹幕判断**（无弹幕高光 + 无字幕 → 低置信）
- 需要精确密度时（渲染路径）才跑全片检测

### 2.4 默认不渲染

`auto` 默认**只产文本证据**（段卡片 + 字幕骨架 + 弹幕高光 + manifest），画面只在 agent 显式请求时渲染。

- 渲染时间：140s → **0**（fast 档 3~5 秒）
- 磁盘：不存图（auto 默认 2~4 张，约 1~2MB；grid 全片才会 38 张）
- 新增命令：`render --plan plan.json`（按 agent 选择渲染）

### 2.5 跳步（允许，默认顺序不是硬规则）

| 情况 | 跳转 |
|---|---|
| 字幕 `null`/`noisy` | 跳过字幕，读弹幕 |
| 弹幕也 `null` | 直接读 coarse 图 |
| agent 觉得某段重要 | 直接点名 fine |

manifest 每段给 `evidence`（各源可用性 + 成本），agent 按成本自行排序。

## 八、设计目标：纯文本可用

> **默认输出不依赖任何视觉能力**；画面只在显式请求时渲染。文本模型能完成"了解 + 筛选"，视觉模型负责"精读"。

两阶段架构：

```
阶段 1：纯文本模型（便宜）→ 读段卡片 + 字幕骨架 + 弹幕 → 筛出值得看的段
阶段 2：视觉模型（贵）    → 只读被筛出的段的 fine 帧
```

纯文本模型的盲区是**可预测的**（证据可用性链会明确标出"字幕 null / **画面未渲染**（auto 默认不生成图，render 才生成）"），所以它知道自己的边界，不会硬猜。

## 十四、不做的事（明确边界）

| 不做 | 理由 |
|---|---|
| 外部翻译接口 | 收益几十 token，维护永久；用「输出 JSON 可 pipe」代替 |
| LLM 摘要/总纲 | 判断层，归 agent |
| 五路广告 advice 双轨制 | **原计划降级为 advice，后改为直接砍**：advice 同样要维护两套字段/两套验证，而 27 条真值里五路**推断**没有贡献独立命中（`adKeywordHits` 已覆盖关键词线索，尚未逐条验证）；降级只是把成本换个名字 |
| 云端 LLM 语义切分 | 贵；本地小模型够用 |
| 摘要覆盖率保证 | 抽取式必有遗漏，全文落盘兜底 |
| 分词器（为了关键词可读） | 索引只用于决策，破零依赖不值 |
| 插件生态 | 单人维护不起「平台 × 信号」参数面 |

## 十六、验收标准

| 项 | 标准 |
|---|---|
| 文本链路成本 | 40 分钟视频 ≤ 3k token（卡片 + 骨架，零帧） |
| 默认不渲染 | `auto` 不生成任何 jpg；`render` 才生成 |
| 纯文本可用 | 文本模型能回答"这视频讲什么、哪段值得细看" |
| 三轨 | coarse 永远可跑；algorithm 默认；adaptive 只在两源低置信 + 授权后 |
| 授权三档 | on 自动开（仅 confidence≥0.7）、off 不开、ask 只标记不渲染 |
| 缺失处理 | 无字幕/无弹幕时 `null` + `confidence: 'none'`，不出现 `0` |
| 摘要质量 | 每段 head 能独立说明段落内容（人工抽检 5 条） |
| 广告召回 | 两路 ≥ **七路**基线（1.0.29）的 80%（否则退回折中） |
| 性能 | 纯文本 **fast 档** <5s（**定义**：40 分钟视频、缓存命中不含下载、**跳过全片场景检测**、含字幕/弹幕 API + 切段 + 摘要）；coarse 单张 <10s |
| 测试 | 全量通过（242 → **约 290**：段卡片/情绪/三轨/类型判定/报价/render/低置信图 各 5~8 用例） |

## 附：设计原则——结论配证据

fisheye 给的是"结论"（情绪浓度/可压缩性/类型判定/低活跃），但**不能全信 agent，结论要配原始证据**——让 agent 能一眼验证，而不是照单全收。

| 结论字段 | 配的证据 | 成本 |
|---|---|---|
| `danmakuEmotion.value` | `top` 3 条原文 | ~40 token |
| `subsEmotion.value` | 骨架 head/info（原文句） | 已在 |
| `compressible: false` | `sample`（抽出来是哪些句） | ~30 token |
| `type: 'slides'` | `evidence`（判据命中明细） | ~20 token |
| `lowActivity: true` | `sample`（段内 2~3 条弹幕） | ~30 token |
| `adHits` | 原文（`text`） | 已在 |
| `needsFrames: true` | `inspect.jpg` | 1024 token/张 |

**只给"可能错且影响决策的"配证据**——事实字段（时长/分辨率/字数）和机械字段（段边界）不配。

**为什么值得**：一条误判的成本（agent 读错一张图 1024 / 读错全文 5k）远高于 30~40 token 的样本。
