# 广告识别：两路 detect + 广告词高光

> 2.0 模块文档。总纲见 [00-总纲.md](./00-总纲.md)；原始复盘见 [广告识别复盘.md](../广告识别复盘.md)。

## 一句话

广告识别从「替 agent 判断」降级为「给 agent 线索」：两路信号影响取帧，`adKeywordHits` 给纯线索，判断归 agent。

### 7.1 保留与删除

| 保留（影响决策） | 删除（曾是七路里的五路） |
|---|---|
| `danmaku-density` → 低活跃段 | `mark`（数字打点：UP 主/观众定制行为，不可迁移） |
| `danmaku-keywords` → 广告词命中 | `head`（片头强信号：只对特定 UP 主有效） |
| `adKeywordHits`（纯线索，不影响决策） | `buy`（消费回溯：依赖特定话术，与 keywords 重叠） |
| — | `sub-keywords` / `sub-patterns`（台词族：依赖字幕质量，真值覆盖率低） |

> **为什么从"降级为 advice"改成"直接砍"**：advice 同样要维护两套字段/两套验证，而 27 条真值里五路**推断**没有贡献独立命中（尚未逐条验证）。降级只是把成本换个名字。

### 7.2 两个输出

#### ① 低活跃段（影响取帧）

```js
lowActivitySegments: [{ from: 343, to: 430, lowDensity: true, sample: [...] }]
```

- 由 `danmaku-density` 产出（密度低谷 = 低价值代理）
- **不是"广告段"**——不知道是不是广告，只知道"观众不互动"
- `sample` 给段内 2~3 条弹幕原文（结论配证据）

#### ② 广告词高光（纯线索，不影响决策）

```js
adKeywordHits: [{ t: 343.2, text: "已下单未付款望发货" }]
```

- 匹配 `AD_KEYWORD` 正则（金主/恰饭/商单/硬广/软广/赞助/推广/接广/带货/下单/优惠码）
- **去重 + 限量**（最多 50 条）
- 同段并置：挂到段卡片里，agent 读卡片时上下文就在眼前

### 7.3 降权而非跳过

```
subtractAds（完全跳过）→ weightSegments（低活跃段降权 w = 0.3）
```

- `w=0` 退化成完全跳过，`w=1` 退化成照常——不是新增特例，是更通用的模型
- 配置：`FISHEYE_LOW_ACTIVITY_WEIGHT`（默认 0.3）
- **落点**：只在 render 的 algorithm 轨生效（采样密度降权）；纯文本链路只标布尔 `lowActivity`，不用 w

**为什么降权**：完全跳过时误报 = 整段内容被删（灾难性）；降权时误报 = 只降权（可恢复）。

### 7.4 与字幕摘要的复用

`adKeywordHits` 同时用于**剔除字幕摘要里的广告口播**（同一个信号两个用途）——字幕摘要的四铁律之一。

### 7.5 平台契约

```js
// bilibili
adKeywords: ['金主', '恰饭', '商单', '接广', '赞助', ...]   // 平台专属词
// local / url
// 无弹幕 → 不做广告检测（adKeywords 为空）
```

平台只声明"能提供什么证据"，不再声明"用哪些信号"（那是 fisheye 的判断）。

### 7.6 验证

- 27 条真值（`test/golden/low-activity/`，第 3 批由 `ad-truth/` 改名）
- 验收：两路召回 ≥ **七路**基线（1.0.29）的 80%
