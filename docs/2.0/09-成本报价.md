# 成本报价

> 2.0 方案模块文档。总纲见 [00-总纲.md](./00-总纲.md)；设计背景见 [fisheye-2.0-方案.md](../fisheye-2.0-方案.md)。

### 12.1 为什么从"规划"改成"报价"

1.0.29 的预算规划（密度/张数/降级/精读预扣）是**替 agent 取舍**，和"判断归 agent"冲突。2.0 改为：fisheye 只**报价**，agent 决定买什么。

### 12.2 计费基准：DSV4.1 Flash（我们自己用的模型）

公开规则（DeepSeek 官方）：**每张图最多 1024 token**，图片自动缩放到约 1300×1300，**与原始尺寸无关**（2000×2000 与 5000×5000 同值）。fisheye 的 3x3/5x5 拼图（1920×1080 / 3200×1800）缩放后均为约 1708×966 → 精确约 945~968 token，报价取上限 **1024**（保守）。

但**"每图 384"是 Flash 自己的规则，不是通用规则**——其他模型按 tile / 像素 / 固定值计费，偏差方向和幅度都不同：

| 模型 | 单图实际 | 对常量 1200 的偏差 |
|---|---|---|
| **DSV4.1 Flash** | ~1024（上限）/ ~945（精确） | 高估 **1.17×** |
| Gemini | ~258 | 高估 4.7× |
| GPT-4o | ~1105 | 接近 |
| Claude | ~1600 | **低估 0.75×** |
| Qwen-VL | ~1300 | 略低估 0.92× |

所以常量 `1200` 对 Flash 是**高估 1.17 倍**（1200/1024），对 Gemini 高估 4.7 倍——必须按模型换算：

```
单张成本 = 基准（flash 1024）× 该模型图片倍率
```

> 推论：「竖屏 3 倍」的假设对 Flash 作废（自动缩放让尺寸无关）；对其他按 tile 计费的模型仍部分成立。
>
> **重要含义**：5x5（25 帧）拼图在 Flash 下**仍是 1024**（精确约 945~968），不是 3800 —— 旧常量 3800 是"1200/张 × 3.2 倍"时代的遗产，已废。fine 与 coarse 同价（都是"一张图"）。

### 12.3 基准（可量化、不含优化技巧）

| 基准 | 定义 | token（DSV4.1 Flash） |
|---|---|---|
| `perFrame` | 1 fps 逐帧独立输入：2400 帧 × ~1024，**不拼图** | **~2,457,600** |
| `fullSubs` | 全读官方字幕 49,757 字（不压缩） | ~49,757 |

> 基准必须写明"不拼图"——拼图法的成本取决于网格/单价/面积修正，变量太多不可量化，不能当基准。

### 12.4 其他模型按倍率倒推

| 模型 | 单图上限 | 倍率（vs Flash） | 对 1200 常量 |
|---|---|---|---|
| **DSV4.1 Flash** | ~1024 | **1.0**（基准） | 高估 1.17× |
| Gemini | ~258 | 0.25 | 高估 4.7× |
| GPT-4o | ~1105 | 1.08 | 接近 |
| Claude | ~1600 | 1.56 | 低估 0.75× |
| Qwen-VL | ~1300 | 1.27 | 接近 |

**图倍率与文倍率分开**：图片按"单图上限"制（倍率差异大），文本按字符 tokenize（倍率 0.8~1.0，差异小）。

### 12.5 报价单形态

```json
{
  "quote": {
    "imageModel": "flash",
    "confidence": "high",
    "baseline": {
      "perFrame": { "token": 2457600, "desc": "1 fps 逐帧独立输入，不拼图" },
      "fullSubs": { "token": 49757, "desc": "全读官方字幕" }
    },
    "text": { "abs": 2000 },
    "coarse": { "rel": 0.51 },
    "fine": { "rel": 0.51, "per": "段" },
    "adaptive": { "rel": 0.51, "per": "张", "note": "帧数按类型：PPT 每页一张 / MV 6~20 张 / 录屏稀疏" },
    "lowconf": { "rel": 0.51, "per": "张", "note": "低置信拼图，9 格/张" },
    "segmentCount": 10,
    "allIn": 13248,
    "cached": false
  },
  "budget": {
    "limit": 5000,
    "fits": false,
    "fitsWhat": "text + coarse + 1 段 fine（4048）"
  }
}
```

> 数值口径：`coarse/fine/adaptive/lowconf` 均为 1024（0.51 × 2000）；`allIn = 2000 + 1024 + 1024×10 = 13248`；`fitsWhat` 为 5000 预算内可买最多的组合（2000 + 1024 + 1024 = 4048；2 段 = 5072 超预算）。

- **agent 侧**：一个 `abs` 锚点（text）+ 各项 `rel` 比例——够它排序和算总价
- **文本也有倍率**（`textFactor`）：字幕 49,757 字在 DeepSeek ≈ 49,757 token，在 GPT-4o ≈ 30k~35k（中文 0.6~0.7 字/token）——报价的 `abs` 按当前配置模型的 `textFactor` 换算
- **人类侧**（report.html）：全部绝对数 + 费用估算（**统一按闲时单价**，注一行"高峰时段 ×2"，不展开时段细节——时段只影响钱，不影响 token 总量）
- **缓存命中**：报价标 `cached: true` → 重跑成本 ≈ 0（DSV4.1 Flash 缓存命中 $0.003/1M，比输入便宜 50 倍）

### 12.6 读图模型由人类配置（`imageModel`）

```json
{
  "imageModel": "flash",
  "readerImageFactor": 2.0,
  "defaultBudget": 5000
}
```

（配置文件路径 `~/.config/fisheye/config.json`；`imageModel` 可选默认 flash，`readerImageFactor` 高级项，`defaultBudget` 不填 = 不限制。）

两个模型要分清：

| 证据 | 谁读 | 模型 |
|---|---|---|
| 文本（骨架/卡片/全文） | 主 agent | 主 agent 的模型（fisheye 不管） |
| 图片（coarse/fine） | 子会话 | `imageModel`（配置） |

`imageModel` 指**读图那一步用的模型**——不管它是子会话读还是主 agent 自己读，都填这个。文本差异小，用 `textFactor` 单独覆盖。

### 12.7 未知模型的三层退路

| 情况 | 处理 | 标记 |
|---|---|---|
| 已收录（flash/gemini/gpt/claude） | 用倍率表 | `confidence: 'high'` |
| 未收录（新模型/中转） | 回退 flash 基准 | `confidence: 'low'` + "可能偏差 3 倍" |
| 自定义倍率 | 用 `readerImageFactor` | `confidence: 'user'` |

**未知模型 = 估算 + 标注，不报错**。本地小模型（Qwen2.5-VL / LLaVA / MiniCPM-V）的图片计费取决于推理引擎（llama.cpp / vLLM / Ollama 不同），没有统一标准——文档说明"按实际引擎实测填倍率"。这类用户有技术基础，最小支持即可。

### 12.8 预算三级（默认零配置）

| 层 | 行为 | 谁用 |
|---|---|---|
| 默认 | **不设硬预算**，只报价 | 大多数人 |
| `--budget N` | **报价上限提示**（超了置 `budget.fits = false`，不硬截断） | 临时控制 |
| `defaultBudget`（配置） | 全局默认预算 | 高级用户 |

默认不限制是故意的：agent 自己知道上下文剩多少，不需要 fisheye 替它管。
`--budget` 也不是硬截断——超了只标记，让 agent 自己决定砍哪项（因为渲染是它按需请求的，fisheye 截不了）。

### 12.9 guidance：最高前提 + 执行顺序

```json
{
  "guidance": {
    "top": "最高前提：在能回答问题的前提下，用最少的 token。能从 text 回答就不要买图；能从骨架回答就不要读全文；能只看 1 段就不要看 3 段。",
    "steps": [
      "默认先读 text（~2k）——大多数问题这一步就够",
      "text 不够才买 coarse（~0.51×）",
      "fine 只买确定要细看的段（~0.51×/段，5x5 也是一张图）"
    ],
    "source": "报价按 imageModel=flash 计算（图片 ~1024 token/张，官方上限）；模型不同按倍率换算"
  }
}
```

`top` 的目标函数（最小化 token），`steps` 是执行顺序，`source` 是数据来源说明。
