# agent 侧使用指南

> 2.0 方案模块文档。总纲见 [00-总纲.md](./00-总纲.md)；设计背景见 [fisheye-2.0-方案.md](../fisheye-2.0-方案.md)。

### 13.1 为什么要有这个

报价单只给价格，不教"怎么花"。skill 把"怎么花"写成流程，所有 agent 复用一份。

### 13.2 证据档位表（三源 × 三档）

| 证据 | 档 1（默认） | 档 2（更细） | 档 3（最贵） |
|---|---|---|---|
| 字幕 | 骨架（~45~140/段） | 全文（~5k/段） | 字幕带图（~1024，无文本时兜底） |
| 弹幕 | 情绪分 | 高光列表 | 原始弹幕（可选） |
| 画面 | coarse（~1024） | algorithm（默认渲染档） | adaptive / fine（~1024/段） |

注意两个轴不同：
- **画面三轨**是密度维度（一张图放几帧）
- **字幕三档**是形态维度（压到多细：骨架 → 全文 → 图）

### 13.3 三层流程

```
① 先看有没有   各源档 1：骨架 / 情绪分 / coarse
② 不够再细     档 2：全文 / 高光 / algorithm
③ 最后才是图   档 3：字幕带 / adaptive / fine
```

第 ③ 层是否可用，取决于 `visualTrack` 配置（见 13.7）：
- `on` → adaptive 已自动生成
- `ask`（默认）→ 只有 `visualRequest` 标记，需要你决定
- `off` → 没有 adaptive，只能 coarse/fine

### 13.4 三轨怎么选（画面）

| 问题 | 轨道 |
|---|---|
| 这视频讲什么 | text（2k） |
| 画面里大概有什么 | coarse（1 张） |
| 某段画面细节/文字 | fine（该段） |
| 无字幕无弹幕 | 授权后 adaptive（PPT 每页 / MV 密抽 / 录屏稀疏） |
| 有字幕弹幕时的默认 | algorithm（auto 已算好，agent 不用手动选） |

### 13.5 fine 的准入门槛（硬约束）

**三条全满足才买 fine，否则不买：**

1. **问题需要画面细节**：文字/数字/图表/动作，且 text 与 coarse 都答不了
2. **只需要 1~2 段**，不是全片
3. **能说出"要看哪一段的什么"**——说不出就是没想清楚，不买

**fine 不是"更准"，只是"更细"**：
- fine 提高的是分辨率，不改变"这段讲什么"——那是 text 的事
- 指望 fine 更准，是拿它做它不擅长的事（语义理解）

**"保险"不是买 fine，是买 coarse**：
- coarse 一张覆盖全片（1024），用来确认"有没有东西"
- fine 是精确（1024/段），用来回答"这个细节是什么"
- 两者不是"粗细"的区别，是"覆盖"vs"精确"的区别

### 13.6 数据置信度低时看样本库

fisheye 给的是"量级"，不是"精确结论"。遇到以下信号时，**不依赖统计数字，改读 `top` 字段的样本**（3 条原文，~40 token）：

| 信号 | 含义 | 动作 |
|---|---|---|
| `confidence: 'low'` | 样本量不足（弹幕 <20 条） | 看 `top` 样本 |
| `suspect: 'spam-heavy'` | 重复度高（dupRatio > 0.4），可能刷屏 | 看 `top` 样本（已去重，各取 1 条） |
| `dupRatio > 0.4` | 同上 | 看 `top` |
| 数字与直觉冲突 | 比如"情绪高"但视频明显平淡 | 看 `top` 验证 |

**为什么看样本而不是读原始弹幕**：原始弹幕几千条（几千 token），样本 3 条（~40 token）——**够判断，且便宜 50 倍**。

样本示例（看内容就知道真假）：

```js
top: [
  { t: 4.3, text: '这是所有改版里最可爱的肥猫！' },   // 真评论
  { t: 1.4, text: '哈莎神之八秒' },
  { t: 6.9, text: '怎么感觉要火' }
]
```

### 13.7 收到 `visualRequest` 怎么办（取决于 `visualTrack` 配置）

`visualTrack` 是人类配的三档，决定"两源低置信时是否读图"：

| 档位 | fisheye 的行为 | agent 该做什么 |
|---|---|---|
| `on` | 类型判定命中且 confidence≥0.7 → **自动开 adaptive** | 什么都不用做，图已经有了 |
| `ask`（默认） | 只标记 `visualRequest`（类型/建议帧数/成本），不渲染 | **agent 决定**：值得看就 `render --track adaptive`，不值得就忽略 |
| `off` | 永不开启 | 没有 adaptive 可买，只能 coarse/fine |

**`visualRequest` 不是必须响应**——它是"我这边没文本证据了，要不要看图你定"，不是"快给我授权"。

判断标准同 fine 的门槛：问题真需要画面 → 授权；只是想"保险" → 忽略（或买 coarse）。

### 13.8 反例（别这样）

- 问"这视频讲什么"却直接买 fine（fine 与 coarse 同价 1024，但 fine 给的是"某段细节"不是"全片概览"——买错了对象，不是买贵了。全片买 fine 是 1024×10=10240，coarse 只要 1024，差 10 倍）
- 不确定就全买（预算爆炸）
- **把 fine 当"更准"的必选项**（它是"更细"，不是"更准"）
- **为了"保险"买 fine**（保险该买 coarse）
- 买 fine 却说不出"要看哪段的什么"（没想清楚就买）
- 把报价里的数字当"必须花完的预算"

### 13.9 报价怎么读

- `text` / `coarse` / `fine` 是**单价**
- `allIn` 是全买总价（**不是推荐**）
- `fitsWhat` 是"预算内能买什么"（给过 budget 才有）
- **没有"套餐"**——自由组合；上面的流程是建议，不是必选
