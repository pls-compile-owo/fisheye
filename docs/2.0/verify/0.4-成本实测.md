# 0.4 成本优先实测（第 0 批验证）

> 核对时间：2026-11-18。核对「只读文本 vs auto 默认」的成本，验证省 **25~32 倍**（不是 47 倍）。

## 一、两个对照端点

| 端点 | 构成 | token |
|---|---|---|
| **auto 默认**（1.0.29） | 字幕全文 + 拼图 | 51k ~ 64k |
| **只读文本**（2.0） | 段卡片 800 + 骨架 1,200 | **~2,000** |

## 二、auto 默认成本核对

- 字幕全文：设计文档实测 **49,757 token**（可汗 2255s 英文 AI 字幕）。
- 落盘核对：`out/BV1WhaA6hE7s-official-subs.txt` = 68,265 字符 / 1,023 行（**字符口径，含 `[00:15]` 时间戳格式**；与 49,757 的 token 口径约 18% 差异，量级一致，不影响结论）。
- 中文翻译轨：26,869 字符 / 540 行（落盘）。
- 拼图：1~12 张（auto 硬上限 12，40 分钟视频通常 2~4 张，预算封顶 1 张）。
  - 按旧常量 1,200/张：49,757 + 1,200 ≈ **51k**（1 张）~ 49,757 + 14,400 ≈ **64k**（12 张）。

## 三、只读文本成本核对（demo 实测）

用可汗视频跑摘要 demo，骨架（head+info+kw+claims+numbers）实测：

| 轨 | 段数 | 骨架 token（实测） |
|---|---|---|
| 中文（demo3，TF-IDF） | 9 | ~1,300 |
| 英文（demo2，TF-IDF） | 9 | ~900 |

只读文本 = 骨架（~900~1,300 实测）+ 段卡片（~80/段 × 10 = 800）≈ **1,700 ~ 2,100**，落在 2,000 目标区间内。

## 四、倍率核对

- 51,000 / 2,000 = **25.5 倍** ✓
- 64,000 / 2,000 = **32 倍** ✓

**结论：省 25~32 倍成立（不是 47 倍——47 倍是「最贵对照」95k/2k，仅作上限参考）。**

## 五、与 0.5（图片 348→1024）的交互

- 图片单价 348→1024 **不影响 25~32 倍**：`auto 默认` 里字幕全文（49,757）占 97%，拼图（1 张 1,200→1,024）只占 <3%。图片单价 ×3 只让 51k 变成 ~50.8k，比例几乎不动。
- 图片单价变化影响的是 **agent 按需读图**阶段的边际成本（coarse/fine ×3），不影响「默认只读文本」的省 token 结论。

## 六、遗留

- 「只读文本 2,000」里的段卡片（~80/段）目前只有设计目标值，无 demo 直接产出——第 1 批 `segments.mjs` 实现段卡片后用真实数据回填。
- auto 默认的「通常 2~4 张拼图」是设计文档口径，未在本机重跑完整 auto（需下载 + 抽帧 + 场景检测，成本高）；以文档实测 51k 为基准核对。
