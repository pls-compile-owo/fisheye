# 口径变更记录：图片单价 348 → 1024

> 变更时间：2026-11-18
> 决策依据：[0.5 计费基准核对](./0.5-计费基准核对.md)（第 0 批验证）
> 决策人：用户（"按官方 1024 上限重新定成本口径"）
> 影响：`docs/2.0/` 全部模块 + `HANDOFF.md` + 已实现的 skill

## 一、为什么改

设计文档 09 原本用的 **348 token/图**，来自已退休的 `deepseek-v4-flash-vision-exp` 模型（每图上限 384、缩放约 800×800）。

当前官方（`deepseek-flash` vision）规则整体变更：

| 项 | 旧（已退休模型） | 当前官方 |
|---|---|---|
| 每图上限 | 384 token | **1024 token** |
| 缩放基准 | ~800×800 | **~1300×1300** |
| 下限（放大） | — | 总像素 < 544×544 |

来源：[Vision 文档](https://api-docs.deepseek.com/guides/vision#token-usage)、[Token 用量计算](https://api-docs.deepseek.com/quick_start/token_usage)

**这不是 ±10% 的误差，是模型换代导致的口径更换。**

## 二、新口径（fisheye 用保守值）

fisheye 的拼图分辨率：

| 拼图 | 生成参数 | 分辨率 | 缩放后 | token |
|---|---|---|---|---|
| 3x3（auto/coarse） | `scale=640:-1,tile=3x3` | 1920×1080 | 1708×966 | **~945** |
| 5x5（fine） | 同上 | 3200×1800 | 1708×966 | **~945** |
| local 3x3 | `scale=480:-2` | 1440×810 | 略低于 1300×1300 | ~700~900 |

16:9 图的精确算法（官方网格）：`rows × (columns + 1) + 2`，其中 `rows = ceil(966/14/3) = 23`，`columns = ceil(1708/14/3) = 41` → `23 × 42 + 2 = **968**`（约 945~968）。

**报价采用 1024（上限）作为安全口径**——不会低估成本；精确值约 945~968，偏差 <8%。

## 三、改了哪些数

| 项 | 旧（348 基准） | 新（1024 基准） |
|---|---|---|
| 图片单价 `perImage` | 348 | **1024** |
| text 锚点 | 2000 | 2000（不变） |
| coarse rel | 0.17 | **0.51**（1024/2000） |
| fine rel | 0.17 | **0.51** |
| adaptive rel | 0.17 | **0.51** |
| lowconf rel | 0.17 | **0.51** |
| allIn（10 段 fine） | 5,828 | **13,248**（2000+1024+1024×10） |
| `visualRequest.costEstimate` | 帧数×348（6 张=2088） | **帧数×1024**（6 张=6144） |
| 5000 预算内能买 | text+coarse+7 fine | **text+coarse+1 fine（4,048）** |
| 基准 `perFrame`（1fps 2400 帧） | 835,000 | **2,457,600**（2400×1024） |
| 模型倍率（vs flash） | gemini 0.74 / gpt 3.2 / claude 4.6 | **gemini 0.25 / gpt 1.08 / claude 1.56** |
| "对常量 1200 的偏差" | flash 高估 3.4× | **flash 高估 1.17×**（1200/1024） |

## 四、什么没变

- **"默认只读文本省 25~32 倍"不变**——它比较的是 text 锚点（2000）vs 旧全读链路（51k~64k），与图片单价无关
- text 锚点 2000 不变（段卡片 800 + 骨架 1200）
- 三层流程、fine 门槛、授权三档、证据档位——都不变

## 六、给未来执行者的提示

1. **别再用 348**——它在文档里只应作为"旧口径"出现（本文件 + 09 的说明）。
2. **写代码时用配置**：`FISHEYE_TOKENS_PER_GRID` 默认 1024，不要硬编码。
3. **agent 看到的报价值是 1024/张**；如果用户配了别的模型，按倍率换算（`imageModel`）。
4. **1024 是上限**：精确值约 945~968，agent 按 1024 算会略保守（安全方向）。
5. **第 0 批的 0.1/0.2/0.3/0.4 结论不受影响**（它们不依赖图片单价，除 0.4 的"读图边际成本 ×3"）。
