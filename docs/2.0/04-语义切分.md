# 语义切分：外挂保留，默认纯 JS

> 2.0 模块文档。总纲见 [00-总纲.md](./00-总纲.md)。

## 一句话

语义切分只做「结构信号」（话题边界），不做「判断」。默认纯 JS（零依赖），需要更高质量时外挂 `SEMANTIC_CLI`。

### 6.1 两档实现

| 档 | 实现 | 依赖 | 质量 |
|---|---|---|---|
| 默认 | `lib/semantic-core.mjs`（char-bigram 词法漂移 + top-k 峰值） | 零 | recall 0.67~1.0（合成数据实测） |
| 外挂 | `SEMANTIC_CLI`（stdin JSON → stdout JSON） | 由实现决定 | 取决于模型 |

### 6.2 外挂契约

```
输入:  stdin 或第一个参数为 JSON：[{ "t": 秒, "text": "台词" }, ...]
调用:  python cli.py <input.json> [--n-bkps 5]
输出:  stdout JSON { "segments": [...], "suggestions": [...] }
```

可接入：fastembed（参考实现）、本地小模型（3B~7B）、云端 LLM。

**推荐本地小模型**：免费、离线、窄任务（切分/分类）够用。
**不推荐云端 LLM**：贵，且摘要/总纲本来就归 agent。

### 6.3 与其他模块的边界

| 能做 | 不能做 |
|---|---|
| 找话题边界（结构） | 判断"哪段重要"（判断） |
| 给 `semanticShifts` 字段 | 做摘要/总纲（判断） |
| 作为段边界候选 | 融合进广告检测（毁归因） |

### 6.4 容错与标注

- 切分错误容错高：边界差 5~30 秒、漏切/多切一个点，agent 读到内容能自愈
- 但 manifest 必须标：`boundary: { source: 'lexical' | 'external' | 'fixed', confidence }`
- 切点吸附到句子边界（避免切在句子中间）
- 低活跃段优先整段保留，不切开

### 6.5 什么时候值得上外挂

| 场景 | 纯 JS 够用吗 |
|---|---|
| 日常快筛 | ✅ |
| 段边界差几个点 | ✅ |
| 课程/讲座要精确章节 | ❌ 需要外挂 |
| 法律/医疗要准确分段引用 | ❌ 需要外挂 |
